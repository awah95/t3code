# Divi Workspaces

Open **Settings → Divi Workspaces** on the local T3 server Mac to manage Divi main checkouts and task replicas. Your original Divi checkout is protected. Use **Create copy** to open the replica setup flow for it.

To work on separate modules in parallel, enter a name and choose **Create main checkout**. This prepares a full Divi theme environment with paired Builder and Builder 5 code checkouts and private dependencies from the original checkout's current commits; uncommitted edits stay in the original. Main code setup does not require Docker. Each repository row can open the code in an installed editor or start a T3 thread in that checkout. If setup becomes invalid, the card lists the exact problems and offers **Repair setup**.

Choose **Create replica** on a ready main checkout to make an isolated task workspace from that main's current commits. Later uncommitted edits in the main are not copied. Choose the **Divi** profile for a clean site without plugins, or **Divi with Fluent Forms** for the seeded Fluent Forms environment and its focused tests. Docker must be running to provision a website. Each replica gets its own WordPress site, and replica cleanup does not remove its main checkout.

Each replica shows source changes, its Git revision and source branch, website and database status, and whether WordPress responds. Use a card's **Refresh** to update it, or **Measure storage** when you need its local file size. **Open website** opens a running preview. Database disk usage is separate. Build watchers keep Divi assets updated as code changes; they are separate from agent chats and tests. Use **Open / new thread** to investigate a replica. In a replica chat, choose **Divi Workspace** from **Open a surface** to manage its website and watchers beside the conversation, or open the site in T3's browser or an external browser.

The settings page can start or stop each replica's dedicated WordPress container and its Builder and Builder 5 watchers. The Builder watcher runs the frontend-builder `yarn start` script, which watches the legacy builder and theme styles. Running site cards show a one-time CPU and memory snapshot after storage measurement. Site and watcher controls operate independently; setup and deletion show their current phase in Settings. All replicas share one database container, shown above the list; stopping a site leaves that database running. **Stop all** stops the watchers and websites for every listed replica. The workspace panel also offers these controls and lets you choose an installed editor for each code folder.

To remove a replica, choose **Review deletion** and enter its exact name. If its source has changes, the final action explicitly discards them. Destruction removes that replica's code worktrees, private website and databases; shared media and the original Divi checkout remain. Existing threads remain in T3 Code, but their deleted workspace paths will no longer be available.
